# DMAIC Planner web app

Paste a short description of one process problem. The app suggests one of five
improvement routes (Just Do It, Kaizen Event, DMAIC, DMADV, Not a CPI project), shows the
model's probability for each, labels how far to trust the top choice, explains the top
two routes in plain language and lists starter tools for the top one. It is a Gradio app,
so it also has an API.

The model is `c2-all60-2026-11-26` (`models/phase3/c2/`): MiniLM sentence embeddings and
a class-balanced logistic regression, blended with similarity to the five route
definitions, refit on all 60 labeled narratives. Its card is `models/phase3/c2/README.md`.

Deploying to Google Cloud Run: [`deploy/README.md`](../deploy/README.md).

## Run it

With Docker (nothing else to install):

```
docker build -t dmaic-planner .
docker run --rm -p 7860:7860 dmaic-planner
```

Or with Python 3.12, from the repository root:

```
python -m pip install -r app/requirements.txt
python -m app.main
```

Then open <http://127.0.0.1:7860>. The first Python run downloads the sentence encoder
(about 90 MB) from Hugging Face; the Docker image already contains it. On Linux without
a GPU, install CPU-only PyTorch first
(`python -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.15.0`);
see the note at the top of `app/requirements.txt`.

## Reading the output

- **Percentages**: the model's probability for each route, exactly as computed, adding
  up to 100%. With five routes, 20% each would be a pure guess, and this model's
  probabilities are flat: a top route at 25% to 30% is typical.
- **Confidence label**: read from `confidence_tiers` in `model.json`, which the model
  build sets from cross-validation, never from the app. For this model it is always "Low
  confidence: compare the top two routes", because in cross-validation the gap between
  the top two probabilities did not predict whether the top route was right. Under the
  label the page shows the cross-validated figures: the top route was right about 35% of
  the time, and the right route was among the top two about 63% of the time. A model
  shipped without tiers gets the percentages and a note instead.
- **Top two**: both are named in bold, and both routes are explained. Treat them as a
  short list for a person to decide from.
- **Tools checklist**: the starter tools for the top route from `rules/tool_map.yaml`, plus
  waste-specific tools when the keyword rules spot a waste in the text. Not generated by
  the model.

## Configuration

All settings are environment variables; no code changes are needed.

| Variable | Default | Meaning |
|---|---|---|
| `DMAIC_MODEL` | `DEFAULT_MODEL` in `app/predictor.py` (`c2`) | `c2` (the deployed model), `placeholder` (keyword rules, no model; for tests and deployment checks), or `package.module:factory` (a zero-argument function returning a model with `predict_proba(texts)` or `predict(texts)`) |
| `PORT` | `7860` | Port to listen on. Cloud Run sets it. |
| `HOST` | `0.0.0.0` | Interface to listen on |
| `DMAIC_THREADS` | CPUs available, at most 4 | CPU threads for PyTorch. The deploy scripts set it to the Cloud Run CPU count. |

Switching models for good is one line, `DEFAULT_MODEL = "..."` in `app/predictor.py`; the
deploy scripts read that line.

## What counts as valid input

| Input | What happens |
|---|---|
| Empty, or only spaces | Refused: "The narrative is empty..." |
| Fewer than 15 words (words must contain letters) | Refused, with the word count. 15 is the dataset's own minimum; the shortest training narrative has 27 words. |
| 15 words up to 5,000 characters | Used whole. The longest training narrative is 4,471 characters. |
| 5,000 to 50,000 characters | Cut at the last whole word before 5,000 characters, with a note saying how much was left out |
| Over 50,000 characters | Refused as "a whole document rather than one narrative" |
| Not text (a number, list, object) through the API | Refused: "Expected the narrative as text (a string), but got int..." |

Errors never show a stack trace. In the browser they appear in place of the result; through
the API the reply has `"ok": false` and an `error` message.

## Speed

Measured in the Docker image limited to 1 CPU and 2 GB, as on Cloud Run, on a laptop
(not yet on Cloud Run itself):

| | Time |
|---|---|
| Cold start: container start to first page served (model loaded and warmed) | about 10 s |
| One typical narrative (about 70 words), server time | about 27 ms |
| A narrative at the 5,000-character cap, server time | about 300 to 360 ms |
| One call through `gradio_client` on the same machine | about 330 ms (mostly Gradio's queue round trip) |
| Memory in use | about 490 MB of the 2 GB |

Long text takes longer because the encoder reads at most 254 wordpieces at a time, so a
long narrative is embedded in several chunks. Each reply reports its own `latency_ms`.

## Use it from code (API)

The app has one API endpoint, `/predict`. It takes the narrative as a string and returns
one JSON object. "Use via API" at the bottom of the page shows the same thing.

Python, with `pip install gradio_client==2.7.2`:

```python
from gradio_client import Client

client = Client("http://127.0.0.1:7860/")  # or the Cloud Run URL
result = client.predict(
    "Purchase requests under $5,000 pass through five approvals, and each one waits "
    "in an inbox for one to three days. About a third bounce back for a missing quote. "
    "Everyone agrees the two middle approvals add nothing for small purchases.",
    api_name="/predict",
)
print(result["route"], f"{result['confidence']:.0%}", "|", result["tier"])
print(result["confidences"])
```

curl (two requests: the first returns an event id, the second streams the result):

```bash
URL=http://127.0.0.1:7860
EVENT_ID=$(curl -s -X POST "$URL/gradio_api/call/predict" -H "Content-Type: application/json" \
  -d '{"data": ["Purchase requests pass through five approvals, and each one waits in an inbox for one to three days. About a third bounce back for a missing quote."]}' \
  | awk -F'"' '{print $4}')
curl -s -N "$URL/gradio_api/call/predict/$EVENT_ID"
```

The reply to the Python example (explanations and tools shortened):

```json
{
  "ok": true,
  "route": "Not a CPI project",
  "route_code": "NOT_CPI",
  "confidence": 0.2487,
  "confidences": {"Just Do It": 0.2019, "Kaizen Event": 0.1944, "DMAIC": 0.2016,
                  "DMADV": 0.1534, "Not a CPI project": 0.2487},
  "tier": "Low confidence: compare the top two routes (Not a CPI project and Just Do It)",
  "tier_name": "low",
  "tier_oof_accuracy": 0.345,
  "top2_oof_accuracy": 0.6257,
  "tier_note": "",
  "tagline": "This is not a process-improvement problem.",
  "explanation": "Not a CPI project means this is not continuous process improvement ...",
  "runner_up": {"route": "Just Do It", "route_code": "JUST_DO_IT", "confidence": 0.2019,
                "tagline": "Somebody just go fix it.", "explanation": "Just Do It means ..."},
  "tools": {"Route": ["Management decision memo", "Business case if funding is requested", "..."]},
  "note": "",
  "truncated": false,
  "model_version": "c2-all60-2026-11-26",
  "placeholder": false,
  "model_ms": 31.6,
  "latency_ms": 31.7
}
```

This example is a miss, and a typical one. The narrative describes a flow problem whose
cause everyone agrees on, which the annotation guidelines would route to a Kaizen Event or
Just Do It. The model puts Not a CPI project first and Just Do It second, all within five
points of each other. That is why the page shows the top two and their explanations
rather than a single answer.

`latency_ms` is the server's time for the request (checks, model and tools checklist);
`model_ms` is the model alone. Network time is extra.

## Tests

```
python -m pip install pytest==8.4.2
python -m pytest -q
```

From the repository root, after installing `app/requirements.txt`. `pytest.ini` points pytest at
`tests/` and `app/tests/` and puts `src/` on the import path.

## Files

| File | What it does |
|---|---|
| `app/main.py` | Gradio page, the `/predict` API endpoint, startup |
| `app/service.py` | Raw input to result: checks, model, confidence label, explanations, tools checklist, timing |
| `app/predictor.py` | The model interface, the `c2` loader, confidence tiers, the placeholder and the `DMAIC_MODEL` switch |
| `app/validation.py` | Input limits and the messages for bad input |
| `app/labels.py` | Route names, explanations, the "how to read this" note and the disclaimer |
| `app/examples.py` | The illustrative example narratives (written for the demo, not from the dataset) |
| `app/tests/` | UI, live API and real-model tests (need the app environment) |
| `Dockerfile`, `.dockerignore` | The image: CPU-only PyTorch, the encoder baked in at the revision `model.json` names, non-root user |
| `.gcloudignore`, `deploy/` | Cloud Run deploy scripts and setup steps |
